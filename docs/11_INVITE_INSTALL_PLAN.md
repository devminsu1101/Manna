# 가입자의 홈 화면 설치 안내 계획

> **2026-11-18 기도 홈 개편과 함께 확인:** 이 계획의 매니페스트 `start_url: "/"`는 유지하되 `/`의 목적지가 중보기도실로 바뀐다. 초대 링크 복귀 쿠키와 첫 실행 로딩 화면을 함께 검증한다. 개편 계획은 [`12_PRAYER_FIRST_REDESIGN.md`](12_PRAYER_FIRST_REDESIGN.md).

> **상태 (2026-11-19): 구현됨.** 초대·로그인·가입 신청의 기존 순서를 유지한다. 별도 설치 페이지나 DB·API는 만들지 않는다. 결정 배경은 `07_HISTORY.md`의 D-3633.

## 누구에게 언제 보여 주나

- **마이페이지 수동 메뉴 (2026-11-26):** 홈 화면 앱 실행 상태(`display-mode: standalone` 또는 iOS `navigator.standalone`)면 ‘홈 화면에 추가하기’를 숨긴다. 일반 브라우저에서는 ‘이미 설치했어요’를 선택했어도 수동 메뉴를 유지한다. 이는 설치 여부 자체가 아니라 현재 실행 모드 판정이며, 서버 렌더링 중에는 숨겼다가 클라이언트에서 판정한다. 메뉴 영역은 배경·항목별 구분선 없이 간격으로 구분하고 영역 위에만 가로선을 둔다.

- **로그인했고 공동체에 가입 신청(`pending`)했거나 이미 가입(`active`)한 사람**에게 안내한다. 가입 신청 직후만이 아니라, 이후에도 홈 화면 앱으로 사용하기 전까지 안내한다. 초대 링크를 열었지만 로그인·가입 신청을 마치지 않은 사람에게는 띄우지 않는다.
- 일반 화면에 도착하면 기존 하단 `Sheet`를 자동으로 연다. 중보기도실 집중 모드나 글 작성 중에는 가로막지 않고 다음 일반 화면에서 연다. 가입 신청 직후 `pending` 화면도 대상이고, 이미 가입한 사람의 공동체·기도·마이페이지 진입도 대상이다.
- **X는 현재 화면에서만 닫고 다음 대상 화면에서 다시 연다. ‘오늘 안 보기’는 그날(KST) 다시 자동으로 열지 않고 다음 날 다시 연다.** `localStorage`에는 이 브라우저 저장 공간에서 마지막으로 ‘오늘 안 보기’를 누른 KST 날짜를 기록한다.
- 설치된 홈 화면 앱(`display-mode: standalone`, iOS standalone)에서는 숨긴다. iPhone Safari에서는 이미 설치했는지를 웹페이지가 확실히 알 수 없으므로 **‘이미 설치했어요’**를 선택하면 그 브라우저의 자동 안내를 계속 끈다. 설치 방법을 다시 보고 싶으면 마이페이지에서 수동으로 연다.
- 브라우저·카카오톡 내부 브라우저·홈 화면 앱은 저장 공간이 다를 수 있으므로 닫기 기록도 공유되지 않을 수 있다. 이 규칙의 단위는 기기 전체가 아니라 **현재 브라우저 저장 공간**이다.

초대에서는 `/invite/{code}`에서 공동체 이름 확인 → Google 로그인 → 복귀 → **가입 신청하기**를 누르는 기존 순서를 유지한다. 가입 신청을 먼저 완료하면 설치 후 초대 주소로 돌아오지 않아도 신청 기록은 서버에 남는다. 현재 매니페스트의 시작 주소는 `/`이다. 홈 화면 앱에서 로그인 세션이 이어지지 않으면 다시 로그인할 수 있으며, 가입 신청을 반복하게 만들지 않는다.

## 시트 UI

- 제목은 **“만나를 홈 화면에 추가해 보세요”**. 본문 첫 줄은 **“아이콘을 눌러 바로 기도하러 올 수 있어요”**로 한다. 승인 대기와 이미 가입한 사람 모두에게 맞는 문구다. OS 푸시 알림 권한 요청과는 별도 안내다.
- 시트에는 환경에 맞는 설치 단계만 보여 준다. X는 현재 화면에서만, ‘오늘 안 보기’는 오늘만 닫는다. ‘이미 설치했어요’는 해당 브라우저에서 자동 안내를 계속 끈다. 수동으로 다시 여는 길은 마이페이지에 둔다.
- 설치 가능한 Android 브라우저에서만 **‘만나 설치하기’** 버튼을 보여 준다. 버튼은 브라우저의 설치 확인창을 열며, 사용자가 최종 설치를 승인한다. iPhone에는 동작하지 않는 설치 버튼을 보여 주지 않는다.

## 환경별 시트 내용

| 환경 | 안내와 버튼 |
|---|---|
| iPhone에서 카카오톡으로 연 경우 | 카카오톡 메뉴에서 **Safari로 열기** → Safari 공유 버튼 → 아래로 내려 **홈 화면에 추가** → 홈 화면 아이콘으로 사용. Safari라는 이름을 쓴다. |
| iPhone에서 Safari로 연 경우 | 이미 첫 단계를 마쳤으므로 **공유 → 홈 화면에 추가**만 안내한다. iOS 설치 확인창을 앱에서 직접 열 수 있다고 말하지 않는다. |
| Galaxy에서 카카오톡으로 연 경우 | 카카오톡 메뉴에서 **기본 인터넷 앱으로 열기**를 안내한다. 그다음 아래의 Android 설치 버튼 또는 수동 메뉴를 따른다. 외부 앱으로 한 번에 여는 버튼은 실기기 검증 전에는 약속하지 않는다. |
| Android 설치 요청을 제공하는 인터넷 앱 | **만나 설치하기** 버튼으로 브라우저 설치 확인창을 열어 메뉴를 찾는 단계를 줄인다. `beforeinstallprompt`가 실제로 제공될 때만 버튼을 보여 준다. |
| Android 설치 요청이 없는 인터넷 앱 | 삼성 인터넷이면 **설치 및 바로가기 만들기** 또는 설치 아이콘을, Chrome이면 **앱 설치** 메뉴를 찾도록 안내한다. 기기·버전별 문구는 실기기에서 확인한다. |

카카오톡의 외부 열기 메뉴가 보이지 않으면 현재 링크를 복사해 Safari 또는 기본 인터넷 앱에 붙여넣을 수 있게 한다. 외부 앱으로의 이동과 홈 화면 설치가 한 번에 완료된다고 약속하지 않는다. 설치 안내와 푸시 알림 권한 요청은 별도 단계로 둔다.

## 구현 위치와 확인 기준

- 로그인·공동체 소속·화면 모드·마지막 닫은 KST 날짜를 확인하는 공통 클라이언트 안내 컴포넌트를 앱의 로그인 후 일반 화면에 둔다. 시트는 `components/ui/sheet.tsx`를 재사용한다. `JoinButton`의 로그인 쿠키·가입 신청 API·리더 승인 규칙은 유지한다. 로그인만 마치고 아직 어느 공동체에도 신청하지 않았다면 띄우지 않는다.
- Android 설치 요청 이벤트는 특정 화면에 도착하기 전에 발생할 수 있으므로 일찍 수신해 보관한다. 이벤트가 없으면 수동 안내로 전환한다. 설치 요청이 거절되거나 ‘오늘 안 보기’를 누르면 그날은 다시 자동으로 띄우지 않는다.
- 개발 환경에서 iPhone Safari·iPhone 카카오톡·Galaxy 설치 버튼 있음·Galaxy 수동 안내 상태를 강제로 보여 주는 **미리보기 모드**를 둔다. 이것은 UI 확인용이며 실제 카카오톡 외부 열기와 Android 설치 확인창의 동작 검증을 대신하지 않는다.
- iPhone Safari·카카오톡 내부 브라우저에서 첫 안내, X 후 같은 날 재방문, 다음 KST 날 재표시, 이미 가입한 계정, 설치 후 홈 화면 앱, ‘이미 설치했어요’를 확인한다. Android는 에뮬레이터 또는 실기기에서 설치 버튼 제공 여부와 수동 메뉴 문구를 확인한다.
